# Вендоренное ядро: Flowseal/tg-ws-proxy

Эта папка — **копия файлов из чужого проекта без изменений**. Править их здесь нельзя:
любая правка потеряется при следующем обновлении и, главное, сломает возможность
сравнивать наш код с upstream. Вся наша логика живёт в адаптере
`freeconnect/tgproxy.py`, а не здесь.

## Почему именно эти файлы

Ядро upstream самодостаточно: внутри `proxy/` только относительные импорты, оно не
тянет их графический интерфейс (`ui/`, `windows.py`, `customtkinter`, `pystray`).
Внешние зависимости ядра: `cryptography`, `httpx`, `h2`, `certifi` — объявлены в
`requirements.txt`.

Единственная внешняя ссылка внутри ядра — `from utils.logging_setup import build_log_handler`
внутри `main()` (только при `--log-file`). Мы `main()` не вызываем, поэтому эта
зависимость не мешает; лог пишем своим обработчиком.

## Как обновлять

```powershell
# посмотреть, что нового у них
.\.venv\Scripts\python.exe tools\update_tgws.py --check

# обновить на конкретный тег (скачает и разложит файлы, перезапишет UPSTREAM.json)
.\.venv\Scripts\python.exe tools\update_tgws.py --tag v1.12.0
```

После обновления обязательно: прогнать тесты (`python -m unittest discover -s tests -t .`)
и проверить Telegram вживую. Автоматически ничего не обновляется — только вручную или
через штатный релиз FreeConnect.

## Что обновляется само, без нашего участия

Пул Cloudflare-доменов (`cfproxy-domains.txt` в их репозитории) ядро тянет
само раз в час прямо во время работы (`config.start_cfproxy_domain_refresh`).
То есть самая изменчивая часть данных не требует ни нашего релиза, ни обновления файлов.
